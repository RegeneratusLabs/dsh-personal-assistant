# Translations

English | [中文](i18n.zh.md)

This repository is bilingual: **English is the source of truth**, and a **Simplified Chinese (zh-CN)**
translation is available for the documentation people read most. GitHub has no server-side locale switch,
so the language option is an explicit pair of files plus a switch line at the top of every translated page.

## Available languages

| Language | Code | File suffix | Entry point |
|---|---|---|---|
| English (source of truth) | `en` | `*.md` | [`README.md`](../README.md) |
| Simplified Chinese | `zh-CN` | `*.zh.md` | [`README.zh.md`](../README.zh.md) |

Switch line: English pages start with `English | [中文](…zh.md)`; Chinese pages start with
`[English](….md) | 中文`. Both are directly below the page title.

Not translated by design: code, code comments, shell scripts, config files, commit messages, logs, test
names and identifiers. Those stay English so commands, diffs and issues match across languages.

## Rules for translations

1. **Structure mirrors the source.** Same number, order and level of headings; same tables, lists and
   fenced blocks. Translate heading *text*, not structure.
2. **Fenced code blocks are byte-identical.** Commands, paths, JSON/YAML, and ASCII diagrams are not
   translated inside the fence. Prose around them is.
3. **Links:** translate the link text, keep the URL. A link to another page uses the `*.zh.md` sibling when
   one exists, otherwise the English page. Keep badges and HTML anchors unchanged.
4. **Keep identifiers verbatim:** plugin names and versions, DSH flags, paths, ports, systemd units,
   file names, `@local/*` package names, API names, branch names.
5. **Terminology follows [`i18n-glossary.md`](i18n-glossary.md).** Add a term there first if a new recurring
   term appears.
6. **No added or dropped content.** Every caveat, warning and "not"/"never" survives. When a term has no
   settled Chinese form, keep the English word in parentheses (e.g. `出站流量（egress）`).
7. **Same commit.** English and Chinese changes to a page land together.

## Keeping pairs in sync

`.i18n.json` records, per section, a hash of the English and Chinese prose (excluding the title, the switch
line and fenced blocks). `scripts/docs/i18n-check.mjs` checks that record, the structure and the links:

```sh
node scripts/docs/i18n-check.mjs             # what CI runs: structure, fences, links, recorded pairs
node scripts/docs/i18n-check.mjs --write     # re-record pairing after syncing both sides
node scripts/docs/i18n-check.mjs --coverage  # print the translation coverage table
```

Workflow for any doc change: edit the English page → make the same change in the Chinese page →
`node scripts/docs/i18n-check.mjs --write` → commit both files. CI runs the checker on every push and pull
request, so a one-sided edit fails the build instead of silently drifting.

## Adding another language

1. Add `<name>.<lang>.md` beside each page you translate (e.g. `README.ja.md`).
2. Add the language to the checker's `LANGUAGES` list and to the language table above.
3. Start every page with the switch line for that language and translate the same docs.

## Accuracy and feedback

Translations are LLM-assisted and reviewed before merge; they are maintained in-repo, not auto-generated at
read time. If a Chinese page and its English source disagree, **the English source is correct** — please
open an issue (or a PR fixing both sides) rather than relying on the translation for security or operational
decisions.
