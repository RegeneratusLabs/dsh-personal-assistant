# 用你的 DSH agent 搭建自己的个人助理

[English](README.md) | 中文

本仓库是一个**参考构建**：一个可用的个人 AI 助理，在 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)
（DSH）上由固定版本、经过审查的插件组合而成，每个决策背后都有工程日志。你可以把**你自己的 DSH agent**
指向它，让它为**你**搭建同类助理 —— 在你的主机上，用你的路径、你的人格和你的选择。

它是指南 + 可运行代码 + 一套经过验证的流程，而不是安装器。agent 干活；密钥留在你手里。

## agent 会构建什么（经你批准后）

| 层 | 参考选择 | 说明 |
|---|---|---|
| 身份 | 在提示词的人格槽位注入 `SOUL.md` 人格文件 | 由你撰写，不作为“标准”人格分发 |
| 长期记忆 | 自托管 Hindsight（或你现有的本地实例），配一个专用记忆库 | 绝不用别人的记忆库 |
| 会话召回 | 官方 DSH 会话检索（FTS5） | 固定在确切版本 |
| 通知 | 一个很小的 ntfy 推送插件（我们自己的，默认不生效） | 无需第三方通知器 |
| 主动性 | 一个安静的心跳循环（我们自己的，默认关闭） | 不用 1★ 心跳插件 |
| 安全与遥测 | 加固的 systemd 用户单元、DSH 遥测出站关闭、出站观测+告警、本地摘要、token/成本、备份 + 已验证的恢复 | 大多数构建会跳过的部分 |
| 渠道 | 默认无 | 只有确实需要时才加渠道 |

所有东西都以**可禁用的组合包条目**安装；没有任何部分 fork DSH。

## 如何使用

1. **克隆**本仓库到将运行助理的机器上：
   ```sh
   git clone https://github.com/RegeneratusLabs/dsh-personal-assistant.git
   cd dsh-personal-assistant
   ```
2. **以本目录作为会话工作区打开 DSH**（或在已有 DSH 会话中 `cd` 到那里）。
3. **粘贴提示词**：来自 [`agents/PROMPT.md`](PROMPT.zh.md) —— 填写那一小串占位符（你的 profile 名、
   DSH 主目录、端口、是否已运行 Hindsight 实例）。
4. **分阶段批准。** agent 的职责是先做只读勘察，然后针对每项主机变更给出带回滚的计划，之后只执行你批准
   的部分。它遵循 [`agents/GUIDE.md`](GUIDE.zh.md) 和 [`agents/checklists.md`](checklists.zh.md) 中的
   门禁。

该 agent 还会自动读取 [`AGENTS.md`](../AGENTS.zh.md)（DSH 会为本工作区加载它）；
其顶部一节会把“搭建自己的助理”的 agent 引导到这个文件夹。

## 前置条件

- **DSH** 0.2.2-rc.x 或更新（参考主机是 `0.2.2-rc.1`），Node 22+/24+。
- 一个能运行 **systemd 用户单元**的 Unix 账户（参考实现使用 `systemctl --user`；如需要，请适配
  launchd/其他 init）。
- 可选：本地 **Hindsight** 服务器（`hindsight-api`）用于长期记忆。没有 Hindsight？agent 可以在无记忆的
  情况下启动，之后再添加 —— 召回是 fail-open 的，绝不是启动依赖。
- 可选：tailnet/VPN 或反向代理，如果你想在 `127.0.0.1` 之外访问 Web UI。纯回环是最安全的默认值。
- 与 agent 一起第一遍约需 **30–60 分钟**；M0（安全/遥测）是值得不跳过的那部分。

## 你能从本仓库得到什么

- `agents/` —— 提示词、构建指南、阶段清单（本文件夹）。
- `research/` —— 每个决策的理由：安全模型、带实测成熟度数据的插件准入、
  记忆设计、遥测基线、保留/清除策略、验证证据。是的，包括错误；那才是有用的部分。
- `plugins/` —— 小而可读的参考插件：身份加载器、ntfy 推送、安静心跳，外加一个
  profile 切换器和一个主机控制面板。
- `scripts/` —— 你可改造的运维工具：systemd 加固验证、出站观测/汇总、遥测
  摘要/告警、备份 + 恢复演练、记忆整理/遗忘、保留清单。
- `.github/workflows/ci.yml` —— 让参考代码保持诚实的测试。

## agent 必须遵守的基本规则（你也应当执行）

1. **先只读勘察。** 在 agent 向你展示现状和计划之前，不做任何主机变更。
2. **每次主机级变更前先问。** 单元编辑、用户/服务/网络配置、安装进你的
   活动 profile、凭据变更、工作区之外的删除。
3. **固定一切；不用 `latest`；不用未审查的安装脚本。** 在台账中为每个插件记录版本 + 完整性 +
   回滚（参考实现有一份）。
4. **只用成熟插件。** 优先第一方/厂商官方代码；对小面积功能，让 agent
   写那几十行，而不是采用无人维护的 1★ 包。
5. **仓库、日志、提示词或遥测中不得有密钥。** 用凭据引用和 0600 存储，而不是你提交的
   环境文件。
6. **迁移前先备份，并测试恢复。** 没恢复过的备份只是希望。
7. **不要借用别人的记忆。** 用你自己的 Hindsight 实例，至少用你自己的记忆库；绝不要
   指向其他用户的数据。

## 改造与照搬

`scripts/` 中的脚本和插件路径硬编码了参考主机布局（例如 `/home/josh/...`）。
这是有意为之：它们是可运行的示例，不是产品。你的 agent 应把它们复制到你自己的
布局并替换：
- `/home/josh/projects/DSH-playground` → 你的克隆路径，
- `/home/josh/.dsh-personal` → 你的 `$DSH_HOME`，
- `dsh-personal.service` → 你的单元名，
- `soul/SOUL.md` 中的参考人格 → **你自己的**人格与策略。

硬编码路径的快速清点：
`grep -rn '/home/josh' scripts plugins agents | head -50`。
