# 翻译

[English](i18n.md) | 中文

本仓库是双语的：**英文为权威来源**，并为读者最常阅读的文档提供**简体中文（zh-CN）**译文。GitHub 没有服务端语言切换，因此语言选项由一对显式文件加上每个翻译页顶部的切换行构成。

## 可用语言

| 语言 | 代码 | 文件后缀 | 入口 |
|---|---|---|---|
| 英语（权威来源） | `en` | `*.md` | [`README.md`](../README.md) |
| 简体中文 | `zh-CN` | `*.zh.md` | [`README.zh.md`](../README.zh.md) |

切换行：英文页面以 `English | [中文](…zh.md)` 开头；中文页面以 `[English](….md) | 中文` 开头。两者都紧接在页面标题之下。

## 翻译规则

1. **结构镜像源文件。** 标题的数量、顺序与层级相同；表格、列表与围栏块相同。翻译标题的*文本*，不翻译结构。
2. **围栏代码块逐字节一致。** 命令、路径、JSON/YAML 与 ASCII 图示不在围栏内翻译。围栏周围的正文要翻译。
3. **链接：** 翻译链接文本，保留 URL。指向另一页面的链接，若存在对应的 `*.zh.md` 同族文件就用它，否则用英文页。徽章与 HTML 锚点保持不变。
4. **标识符保持原样：** 插件名与版本、DSH 旗标、路径、端口、systemd 单元、文件名、`@local/*` 包名、API 名、分支名。
5. **术语遵循 [`i18n-glossary.md`](i18n-glossary.md)。** 若出现新的重复术语，先在其中补条目。
6. **不增不减内容。** 每一个限定、警告和“不/绝不”都要保留。某术语尚无定译时，在括号中保留英文（例如 `出站流量（egress）`）。
7. **同一提交。** 英中改动同时落地。

## 保持双语配对同步

`.i18n.json` 按分节记录英文与中文正文（不含标题、切换行与围栏块）的哈希。`scripts/docs/i18n-check.mjs` 校验该记录、结构与链接：

```sh
node scripts/docs/i18n-check.mjs             # what CI runs: structure, fences, links, recorded pairs
node scripts/docs/i18n-check.mjs --write     # re-record pairing after syncing both sides
node scripts/docs/i18n-check.mjs --coverage  # print the translation coverage table
```

任何文档变更的流程：改英文页 → 在中文页做同样的改动 → `node scripts/docs/i18n-check.mjs --write` → 提交两个文件。CI 在每次 push 和 pull request 时运行检查器，因此单边编辑会让构建失败，而不是悄悄漂移。

## 新增另一种语言

1. 在你要翻译的每个页面旁添加 `<name>.<lang>.md`（例如 `README.ja.md`）。
2. 把该语言加入检查器的 `LANGUAGES` 列表和上面的语言表。
3. 每个页面都以该语言的切换行开头，并翻译同样的文档。

## 准确性与反馈

译文由 LLM 辅助生成并在合并前评审；它们在仓库内维护，而不是在读取时自动生成。如果中文页与其英文源不一致，**以英文源为准**——请开 issue（或同时修正两侧的 PR），而不要依赖译文做安全或运维决策。
